# diskcache Security Risk Assessment

## Vulnerability Details

| Field | Value |
|-------|-------|
| **CVE** | CVE-2025-69872 |
| **Advisory** | PYSEC-2026-2447 |
| **Package** | diskcache |
| **Affected Version** | 5.6.3 (current on PyPI) |
| **Fixed Version** | **diskcache-community 5.7.0** (opt-in SafeDisk) / None for original diskcache |
| **Severity** | High (CVSS 7.5) |
| **Type** | Unsafe pickle deserialization |

## Vulnerability Description

`diskcache` uses Python's `pickle` module for serialization. If an attacker can write a malicious pickle file to the cache directory and the application subsequently reads it, arbitrary code execution occurs during deserialization.

**Attack vector**: Attacker writes malicious `.pickle` file to cache directory → Application reads cache → `pickle.loads()` executes arbitrary code.

## Dependency Chain

```
diskcache==5.6.3
  └── pySigma==1.5.0 (requires diskcache>=5.6.3,<6.0.0)
      ├── pysigma-backend-splunk==2.1.0
      └── sigma-cli==3.1.0
```

**Usage in this project**: `sigma_cache.py` uses `diskcache` for Sigma rule conversion caching (`SigmaConversionCache` class). Cache stored at `data/cache/sigma_conversions.json` (actually uses diskcache's directory-based storage).

## Community Fork: diskcache-community 5.7.0

**Update (2026-10-14)**: A community fork `diskcache-community` version 5.7.0 was published on PyPI (2026-10-11). It introduces an opt-in `SafeDisk` implementation designed to mitigate the unsafe-deserialization vulnerability.

**Important caveats**:
- Version 5.7.0 still uses the original `Disk` by default. Must explicitly configure `SafeDisk` to enable mitigation.
- The fork is very new — review its code, provenance, compatibility, and tests before adopting.
- Both distributions install the same `diskcache` import package. **Must uninstall original before installing fork** — do not install both side by side.

### Migration Path (if adopted)
```bash
pip uninstall diskcache
pip install diskcache-community==5.7.0
```

```python
# In sigma_cache.py
from diskcache import SafeDisk  # instead of Disk
cache = SafeDisk("data/cache", ...)  # opt-in safe mode
```

## Exposure Analysis

| Factor | Assessment |
|--------|------------|
| **Attack vector** | Local file write to cache directory |
| **Prerequisites** | Attacker must have write access to cache directory (`data/cache/`) |
| **Trigger** | Application reads malicious cache entry |
| **Impact** | Arbitrary code execution as application user |
| **Network exposure** | None (local file system only) |

## Risk Assessment

| Factor | Rating | Rationale |
|--------|--------|-----------|
| **Likelihood** | Low | Requires local file write access + cache read |
| **Impact** | High | Arbitrary code execution |
| **Overall** | **Medium** | Low likelihood, high impact |

**Why not Critical**: Requires local file system write access. Not remotely exploitable without prior compromise.

## Current Mitigations

1. **Cache directory permissions**: Ensure `data/cache/` is only writable by the application user
2. **No untrusted input**: Cache only stores Sigma rule conversion results generated by the application itself
3. **No external cache population**: Cache is populated only by the application's own Sigma conversion pipeline

## Residual Risk Decision

**Decision**: **Accept with documented compensating controls + evaluate fork**

**Rationale**:
- Original `diskcache` 5.6.3 has no patched version on PyPI
- Community fork `diskcache-community 5.7.0` offers opt-in `SafeDisk` mitigation
- `diskcache` is a transitive dependency of `pySigma` (required for Sigma rule conversion)
- Attack surface is limited to local file system access

**Compensating Controls**:
1. Set cache directory permissions to `0700` (owner read/write/execute only)
2. Run application under dedicated service account
3. **Evaluate `diskcache-community` 5.7.0 in a branch** — test `SafeDisk` compatibility with `pySigma`/`sigma_cache.py`
4. Monitor for original `diskcache` 5.6.4+ release

## Monitoring

- Watch for `diskcache` 5.6.4+ release on PyPI
- Watch for `diskcache-community` updates and adoption
- Monitor CVE-2025-69872 for updates
- If adopting fork: run full test suite + `pip-audit` before merge

## Compliance Note

This residual risk is **accepted with documented compensating controls + active evaluation of mitigation fork**. The risk is recorded in the project's risk register and will be reviewed at each release.
